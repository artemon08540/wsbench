# Журнал дослідження

Що відбувалося під час підготовки експерименту: рішення, проблеми та їх розв'язання.
Матеріал для Розділу 2 (методика, обмеження) і Розділу 3 (результати), а також для відповідей на захисті.

## 1. Пілот (жовтень 2026)

- 5 сторінок, М1 і М3, 3 повтори (30 прогонів), результати в `results/pilot3/runs.csv`.
- М3 у середньому в 4,5 раза повільніший за М1, у 15 разів більший трафік, у 5 разів більше пам'яті, в 11 разів більше процесорного часу.
- На 5 сторінках тест Вілкоксона не може дати p < 0,05 (мінімально можливе p = 0,0625), навіть коли ефект
  максимальний (δ = −1). Звідси вимога до основної вибірки: не менше 20 сторінок.
- Критерій Фрідмана не рахується для двох методів (потрібно щонайменше три).

## 2. Формування основної вибірки (10.11.2026)

**Вимоги керівника:** ≥ 20 сторінок, ≥ 5 кожного типу (SSR / SPA / гібрид), магазини не лише українські.

**Інструмент:** команда `discover` – автоматичне попереднє визначення типу рендерингу без налаштування
селекторів (картки знаходяться евристично, тип – за часткою назв товарів у сирому HTML:
< 20 % SPA, 20–80 % гібрид, ≥ 80 % SSR). Потім `check-site` з точними селекторами.

**Проблеми й рішення:**
- Більшість великих магазинів блокують запити Python (HTTP 403/429): MediaMarkt, Conrad, BestBuy.ca,
  JB Hi-Fi, Argos, Currys, Otto, bol.com, Micro Center, Alza, Proshop, notebooksbilliger, Citrus,
  euro.com.pl, Media Expert, Brain, Gigantti (Vercel 429), Jimms (Cloudflare). Їх виключено:
  обхід захисту не виконується (етичні принципи дослідження). Це саме по собі результат –
  реальна частка сайтів, доступних для автоматизованого збору, обмежена.
- Перша версія `discover` помилково визначала SSR-сайти як SPA: за назву бралася найдовша
  текстова частина картки (характеристики, умови доставки). Виправлено: пріоритет – заголовки
  й елементи з `title`/`name` у класі; тексти з кількома двокрапками (характеристики) відкидаються.
- Нестабільність сайтів: Coolblue між пілотом і основною вибіркою змінився з SPA на SSR;
  стара адреса ноутбуків Eldorado тепер веде на головну (взято категорію телевізорів);
  `verkkokauppa_phones` (/phones/phones) виявилась вітриною без списку – замінено на android-phones.

**Справжніх гібридних сторінок у класичному розумінні майже немає.** Тому гібрид визначено
операційно: перша порція товарів є в HTML, наступну сайт довантажує JavaScript-ом після кнопки
«Показати ще» (М1 бачить лише першу порцію, М3 натискає кнопку). Для цього в М3 додано
натискання кнопки (`load_more_selector`, `load_more_clicks`) з очікуванням нових карток.

**Підсумок:** 22 сторінки, 10 сайтів (магазинів), 4 країни (Україна, Польща, Франція, Фінляндія):
- SSR (11): Foxtrot ×2, x-kom ×3, LDLC ×2, Hotline ×2, Boulanger, Eldorado;
- гібрид (5): Telemart ×3 (48 + 48 після кнопки), Moyo ×2 (24 + 24);
- SPA (6): Power ×3, Verkkokauppa ×3.

**Межа дослідження:** одиниця спостереження – одна (перша) сторінка каталогу. Класична пагінація
за адресою (`?page=N`) не розглядається: усі методи виконують її однаково (повторення того самого
запиту), тому порівняння вона не змінює, а навантаження на сайти й обсяг еталону зростають у рази.
Довантаження кнопкою розглядається, бо саме воно відрізняє методи.

## 3. Налаштування М2 (внутрішній API)

**Інструмент:** команда `find-api` – відкриває сторінку в браузері, записує всі JSON-відповіді,
шукає в них список із тими самими назвами, що на сторінці (визначає `items_path`, поле назви й ціни),
повторює запит без браузера й cookie і перевіряє robots.txt адреси API.

**Результати:**
- SSR і гібриди (13 сторінок): JSON зі списком товарів немає – дані приходять у HTML. М2 n/a.
- Hotline, Boulanger, Eldorado: знайдені JSON – віджети відгуків/реклами (6–28 товарів із 40–48),
  а не каталог. Відкинуто; `find-api` тепер позначає такі випадки статусом `partial`.
- Power (3 сторінки): `/api/v2/productlists` – 36/36 товарів, назви й ціни збігаються. **М2 працює.**
  У 5 разів швидше за М3, трафік у ~100 разів менший, пам'ять у ~7 разів менша.
- Verkkokauppa (3 сторінки): API `search.service.verkkokauppa.com` спочатку дав 48/48, але в пробному
  прогоні з еталоном М2 мав повноту 10–31 %. Причина: без браузера API віддає **інший набір товарів**,
  ніж бачить відвідувач (збіг 16–43 з 48, змінюється). Спроби: новий ідентифікатор сесії на кожен
  прогін, попередній запит сторінки для отримання cookie – не допомогли. Висновок: результат залежить
  від стану сесії, який формує JavaScript. **М2 n/a.** `find-api` тепер порівнює назви відповіді
  зі сторінкою (статус `replay_mismatch`), а не лише кількість.
- Robots.txt: основний сайт Verkkokauppa забороняє `/api/`; API лежить на іншому хості без robots.txt
  (за RFC 9309 правила діють окремо для кожного хоста). Питання стало неактуальним після виключення М2.

**Висновок для роботи:** М2 застосовний лише на 3 з 22 сторінок (14 %). Для статистичної перевірки
цього замало (на 3 сторінках мінімальне p Вілкоксона = 0,25), тому для М2 наводяться описові
показники й розмір ефекту. Обмежена застосовність і нестабільність недокументованого API – один із
головних результатів: найдешевший метод є найменш універсальним і найменш стійким до змін сайту (М13).

## 4. Еталон (ground truth)

- Чернетки створено командою `gt-draft` (метод М3), кожну перевірено вручну в браузері
  (назва, актуальна ціна, пропущені та зайві товари). 22 файли, ~1 000 записів.
- Telemart monitors / videocards (шаблон ідентичний ноутбукам) – вибіркова перевірка:
  кількість товарів, перші й останні 5 записів, усі товари зі знижкою.
- **Знайдена помилка селектора:** на Telemart бралася стара (перекреслена) ціна – у блоці
  `product-cost` лежать і стара, і нова ціни. Селектор змінено на
  `.product-item-cost-column > .product-cost`. Помилка впливала на точність полів М1, М3, М4 –
  це приклад, навіщо потрібна ручна перевірка еталону.
- Зміни сторінок під час перевірки: Hotline (агрегатор) – змінилися 2–3 ціни; Boulanger – зник
  рекламний (sponsored) товар, 40 замість 41. Еталон фіксує стан сторінки на момент перевірки.
- Verkkokauppa: у браузері з cookie список товарів інший, ніж у «нового відвідувача», тому
  перевірка – у приватному вікні. Порядок товарів для еталону не важливий (зіставлення за назвою).
- На Eldorado 15 товарів «Продано» без ціни – у еталоні ціна порожня.
- Залишилось: повторна розмітка ~5 сторінок через кілька днів (`gt-agreement`, поріг ≥ 98 %).

**Обмеження:** вебресурси змінюються в часі; еталон і основний експеримент виконуються в один день.
Прогони йдуть у випадковому порядку (зерно 42), тому зміни сайту під час експерименту рівномірно
розподіляються між методами і не спотворюють порівняння.

## 5. Пробний прогін з еталоном (5 сторінок, 4 методи)

- М1: SSR 100 %, гібрид Telemart 50 %, SPA 0 %.
- М3: 100 % скрізь. М4: 100 % на SSR, гібриді та SPA (на SPA і гібриді перемикається на браузер).
- **Foxtrot відповів HTTP 429** (забагато запитів), коли за 16 с до нього звернулися М3, М1 і М4.
  М4 при блокуванні навмисно не перемикається на браузер (це було б обходом блокування) –
  блокування фіксується в показнику М12. Для основного експерименту пауза між зверненнями до
  одного домену збільшена з 2 до 10 с.

## 6. Основний експеримент

```
python -m wsbench run-experiment --sample config/sites_main.yaml --methods M1,M2,M3,M4 --repeats 5 --min-delay 10 --out results/main
```
22 сторінки × 4 методи × 5 повторів = 440 прогонів (М2 n/a на 19 сторінках).
